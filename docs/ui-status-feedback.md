# UI, Status Feedback, and Play Readability

## Goal

The game must make status systems readable, meaningful, and emotionally affecting without overwhelming the player.

## Core HUD requirements

### 1. Primary status panel

The UI should display:

- Zinwave Stability
- Emotional Flux
- Memory Integrity
- Continuity Fracture
- Deep Contamination
- Synchronization

These should be visible during exploration and combat, but not so heavy that they obscure the environment.

### 2. Status color language

Suggested visual language:

- blue = system / stability / continuity
- violet = overload / emotional fracture / node pressure
- gold = anchor / De’juir synchronization / truth stability
- black or dark grey = Deep contamination / corruption

### 3. Event-driven feedback

When statuses rise or fall, provide:

- small visual flashes
- distortion overlays
- audio cues
- subtle world changes
- narrative text hints for major state transitions

### 4. Player-facing readability

The player should always understand:

- which statuses are currently threatening them
- which status triggered the current environmental change
- when De’juir stabilization is available
- when a decision or memory event is likely to change reality or progression

## Environmental feedback

Status changes should also affect the environment:

- flickering lighting
- distorted audio
- fractured geometry
- mismatched textures or visual lag
- delayed interactions

This communicates that the status system is not abstract; it is the world itself becoming unstable.

## Narrative UI

Key narrative states should be represented with minimal but meaningful prompts:

- memory recovered
- identity fracture warning
- reality shift
- De’juir support available
- signal detected

The UI should feel like it belongs to a machine intelligence and a fractured synthetic reality.

## Production requirement

The UI is not optional. It is part of the game’s sense of instability and should be designed with the same care as the narrative and world.
