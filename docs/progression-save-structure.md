# Player Progression and Save Structure

## Goal

The game needs a progression structure that reflects identity instability, memory recovery, and emotional continuity instead of simple leveling.

## Core progression design

The player should not progress by “XP and level up” alone. Progression should come from:

- memory recovery
- status management
- relationship trust with De’juir
- discovered truths about the world
- survival through unstable environments
- continuity preservation in key story events

## Primary progression categories

### 1. Memory progression

The player gains access to:

- personal history fragments
- prior Zero2 versions
- system-level truths
- emotional clarifications
- hidden narrative branches and alternate interpretations

This progression directly affects:
- story understanding
- in-world exploration access
- status stabilization outcomes
- narrative end-state logic

### 2. Identity progression

Zero2’s progression is measured by how much of her continuity can be preserved and how successfully she navigates instability.

The player should feel this through:
- reduced memory confusion
- better control during high-pressure moments
- fewer fractured reality events
- stronger support from De’juir

### 3. Bond progression

De’juir is not just a side character; his presence modifies gameplay and emotional continuity.

Bond progression should increase:
- support actions
- stability during fractures
- narrative trust states
- final decision leverage

### 4. World progression

The game world should unlock in relation to discovered truth and stable continuity.

Examples:
- a region may become navigable only after a memory fragment is recovered
- a route may be hidden until the player stabilizes the node
- an environment may reappear in a new form after a key emotional event

## Save structure requirements

The save system should support:

- story state
- memory state
- status state
- relationship state
- world state / region integrity
- branch decisions
- critical event state

### Save state data model

Each save should include:

- current chapter and scene
- active region and world fold
- memory fragments discovered
- active status values
- current continuity state
- De’juir trust / synchronization level
- major story flags
- optional route / branch decisions
- active environmental instability states

## Save philosophy

The save system should not feel like a generic RPG checkpoint. It should feel like:

- the player is preserving a fragile continuity
- the world can “remember” the player’s failures and choices
- authenticity and continuity matter in a broken reality

## Progression and save design requirement

The game must allow the player to return to unstable worlds without losing the emotional and mechanical impact of their choices.

## Example progression event

If the player loses a memory fragment during a major fracture:

- the story route may change
- the De’juir bond may weaken or strengthen depending on response
- remaining status values may shift
- the region may become more dangerous on reload

This makes memory and continuity feel like real game systems, not just narrative flavor.
